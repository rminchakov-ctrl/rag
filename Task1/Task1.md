# Анализ и выбор технологического стека

Анализ компании и проблем показывает:

- Требования compliance: Упоминание подготовки к SOC 2 — это ключевой сигнал. Компания работает с крупными промышленными гигантами (ABB, Wärtsilä), что подразумевает высочайшие стандарты безопасности и управления данными. Это не просто *конфиденциальность*, это формализованные compliance-требования. Любое решение должно быть развернуто в строго контролируемом периметре (on-premise или VPC).
- География: Наличие офисов в Финляндии и Эстонии (ЕС) подчиняет обработку данных GDPR. Это еще раз исключает использование американских облачных API (OpenAI) для каких-либо данных, содержащих персональную информацию или коммерческую тайну.
- Экономика: Компания уже тратит значительные средства (140 часов на аудит, 4 часа/инженера в неделю). Любое решение должно иметь прозрачную и предсказуемую модель стоимости.
- Цели решения: Система должна не только отвечать на вопросы, но и выявлять пробелы в документации. Это требует тщательного логирования/метрицирования запросов, их анализа и, возможно, дообучения модели.

Итог: Использование публичных cloud-LLM (OpenAI, YandexGPT) и их эмбеддингов полностью исключено из-за compliance-требований SOC 2 и GDPR. Фокусируемся на локальном или приватном облачном развертывании.

## Сравненение LLM-моделей

На основании анализа требований к конфиденциальности (SOC 2, GDPR) и производительности, рассматривались только локально развертываемые модели:
|Модель|Размер|Контекстное окно|Качество|Соответствие требованиям|Применимость|
|:--|:--|:--|:--|:--|:--|
|**Llama 3.3 70B**|70B|128K|5|Полное|**ВЫСОКАЯ** - основной кандидат|
|**DeepSeek-V3**|671B|128K|5|**НЕ СООТВ.** (cloud-only)|Исключена (нарушает GDPR)|
|**Qwen3-30B**|30B|128K|4|Полное|**СРЕДНЯЯ** - резервный вариант|
|**Mistral Small 3**|~20B|128K|3|Полное|**СРЕДНЯЯ** - для менее критичных задач|
|**Llama 3.1 8B**|8B|8K|2|Полное|**НИЗКАЯ** - недостаточное качество|
|**Qwen3 8B**|8B|8K|2|Полное|**НИЗКАЯ** - недостаточное качество|
Рекомендация: 
- Llama 3.3 70B полностью соответствует всем требованиям как по качеству, так и по compliance. 
- Qwen3-30B можно рассмотреть как стартовую (тестовую) площадку.

## Сравненение моделей эмбеддингов

Для обеспечения точного семантического поиска в технической документации:

|Модель|Ключевое преимущество|Размерность|Контекст|Использование|
|:--|:--|:--|:--|:--|
|**BAAI/bge-large-en-v3**|**Эталонное качество**|1024|8192|Основная база знаний, где важен максимум точности.|
|**BGE-M3**|**Гибридный поиск + мультиязычность**|1024+|8192|Проекты со смешанным контентом (англ. + рус./фин./эст.) или где нужен поиск по ключевым словам.|
|**Qwen3-Embedding**|**Поиск в коде и длинный контекст**|1024-2048|**32k**|**Идеально для разработчиков:** поиск по исходному коду, API, логам.|
|**Nomic-Embed-v1.5**|**Экономия ресурсов (Matryoshka)**|768|8192|Быстрое прототипирование, снижение стоимости на хранение и поиск в больших индексах.|
|**jina-embeddings-v3**|**Длинные документы**|1024|8192|Обработка целых технических отчетов, спецификаций, длинных PDF-файлов.|

Рекомендация: использовать ансамбль эмбеддингов.
- Основной векторный индекс базы знаний строить на BAAI/bge-large-en-v3.
- Для обработки запросов, содержащих специфические термины или на других языках, использовать BGE-M3 в качестве fallback-энкодера.
- Для кодовой базы Qwen3-Embedding.

## Итоговое решение

### Модели и обработка данных

Модели
- LLM: Llama 3.3 70B-Instruct (основная)
- Резервная LLM: Qwen3-30B

Эмбеддинги
- Основные: BAAI/bge-large-en-v3
- Специализированные: BGE-M3 (мультиязычность), Qwen3-Embedding (код)

Векторная БД
- Qdrant 2.5+ (основная)
- Pgvector 2.6+ (альтернативная, при наличии PostgreSQL-экспертизы)

### Инфраструктура и развертывание
Оркестрация: Kubernetes (k3s/RKE2)
Мониторинг:
- Логи: Loki + Grafana
- Метрики: Prometheus + VictoriaMetrics
- Трассировка: OpenTelemetry SDK для всех микросервисов + OTel Collector + Grafana
- Хранилище: Ceph/Rook для распределенного storage
Сеть: Calico CNI с политиками безопасности

### Безопасность и compliance
Шифрование: WireGuard для межсерверного взаимодействия
Аутентификация: Keycloak с OIDC
Audit: OpenSearch с криптографическим хешированием логов
Соответствие: Automated SOC2/GDPR compliance scanning

### Архитектурные особенности
Микросервисная архитектура:
- llm-orchestrator: Управление запросами к LLM
- embedding-service: Обработка эмбеддингов
- vector-db-proxy: Абстракция над векторными БД
- analytics-engine: Анализ использования и выявление пробелов
- data-pipeline: ETL для обновления знаний
